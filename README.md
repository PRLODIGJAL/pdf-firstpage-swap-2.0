# PDF 首页替换工具 v2.0（顺序配对版）· pdf-firstpage-swap

把**一批人工签字扫描件**的首页，按顺序替换回一批原 PDF —— **不做任何文件名匹配**。

**原始文件只读，永不改动。**

> 这是 v1 的姊妹版本。v1 是「一份原件 ↔ 一份扫描件，靠文件名相似度配对」，
> 适用原件名不规整、不能靠顺序硬对的场合；**v2 反过来，靠顺序硬对应**。
> 两版并存、互不影响、各记各的上次选择。本仓库是 **2.0 版**，同时收录 **macOS** 与 **Windows** 两份交付。

---

## 它解决什么

现实里的痛点是：**不可能一份一份地扫** —— 十几二十份签字首页，一份一份扫要十几二十分钟。
实际做法是**把纸质文件按文件夹里的顺序摊开，一口气扫成一份多页 PDF**，
然后「第 1 页换到第 1 份原件上、第 5 页换到第 5 份上」。

```
表格第 1 行 ← 扫描件第 1 页        输出 = [扫描件第 N 页] + [原件第 2 页 ~ 最后一页]
表格第 2 行 ← 扫描件第 2 页
表格第 5 行 ← 扫描件第 5 页
```

连相似度门槛都没有 —— 就是硬对应。

### 排队顺序 = 文件夹里按「名称」看到的顺序

**不需要把原件改名成 001、002**（改名会动到用户自己的命名，也不直观）。
排序口径就是 Windows 资源管理器 / macOS 访达点「名称」看到的那个顺序：

- 字母**不分大小写**（`Apple` 与 `apple` 不会被劈成两堆）
- 数字**按数值**排（`WI-9` 在 `WI-10` 前面，不会出字典序的错）
- 现实里怎么用：**纸质文件按文件夹里的顺序摊开，从头扫到尾**，肉眼就对得上
- 中文名的已知边界：按 Unicode 码点排，可能与资源管理器的拼音序略有出入 → 表格里 ↑↓ 手动调

排错了也不用改名：表格里有「↑上移 / ↓下移」，双击某行还能直接指定它用扫描件第几页。

## 怎么跑

两个平台都是**双击启动器**即可，首次会自动准备运行环境（建 `.venv` → 装依赖 → 拉起界面），
之后每次双击秒开。

| 平台 | 入口 |
|---|---|
| macOS | `mac/启动PDF首页替换2.0.command` |
| Windows | `windows/启动PDF首页替换2.0.bat` |

**前置条件**：本机装有 Python 3.9+（Windows 安装时记得勾 `Add python.exe to PATH`）。

命令行同样可用：

```bash
python seq_core.py --src 原件 --scan 扫描件.pdf --out 输出 \
    [--dry-run --recursive --no-scale --overwrite --suffix _已替换 \
     --order name|mtime --rotate "3:90,5:270" --no-auto-rotate --reverse]
```

> ⚠️ `.venv` **不要**随包拷给别人，也不要跨电脑复制 —— 它记着创建时那台机器的 Python 绝对路径。
> 换台电脑第一次双击会自动重建，**不要**手动删掉整个文件夹重来。

## 阻断闸门（五条，命中任一条整批不输出）

1. 原件文件夹不存在
2. 文件夹里没有 PDF（输出目录和扫描件本身会自动排除，所以"没有"是真没有）
3. 扫描件不存在 / 读不出 / 0 页
4. **原件份数 ≠ 扫描件页数** → 写明「原件 20 份、扫描件 18 页（差 2）」
5. 有原件读不出页数（损坏 / 加密）

> ⚠️ 为什么是**阻断**而不是"跳过那一份继续跑"：顺序配对是一条**脆弱链**，
> 中间缺一个 / 多一个，从那一份起**后面全部贴错封面**，而且错得悄无声息。
> 所以这里选了最保守的策略：直接报错、一个都不输出。

## 扫描页方向

### 自动方向（默认规则）

原件首页**横向**的 → 它对应的那一页扫描件默认**左转 90°**（前提：扫描件一律竖着扫）。

- ⭐ **守卫**：那一页**本来就是横向**时（宽 > 高）**不转** —— 说明它已经是横着扫出来的，再转一次反而转反
- ⚠️ 自动值每次按当前的【行 → 页】映射**重算**：页码一动，"这一页是谁的封面"就变了，默认方向跟着变
  —— **跟着横向原件走，不是跟着页码走**

### 人工方向

横版表格在扫描时还是要当竖着扫，会导致名字竖向排列 —— **机器判断不出方向**，所以给了按钮人工判：

```
原件首页 842×595（横版表格）← 扫描页被竖着扫成 595×842
    → 人工点「右转 90°」→ 扫描页显示尺寸变 842×595 → 正好贴合
```

角度按 PDF `/Rotate` 语义：**正数 = 顺时针**。状态：`0 正向 / 90 右转 / 180 倒转 / 270 左转`；
连点两次 = 180°，四次回到原样。

> ⚠️ **顺序不能反**：先 `Page.rotate()` 再 `transfer_rotation_to_content()`，
> 之后 `display_size()` 才是转好的尺寸；贴合决策必须用转好的尺寸比，否则拿竖尺寸去套横原件。

优先级：**人工 > 自动 > 正向**。

## 界面要点

工具栏分成三个模块，**各占一行**：

| 模块 | 按钮 | 语义 |
|---|---|---|
| ① 扫描件页序 | `页序：正序 ⇄ 倒序`（一键切） | **整批重算**：重排所有页码。切一次会把②里手动调过的页码清回默认 —— 所以**必须先定页序再调页码** |
| ② 页码对应 | `↑ 与上行对调` `↓ 与下行对调` + 双击指定 | 行**不动**（行顺序＝名称序，是唯一排队依据），只换"这一行用哪一页" |
| ③ 方向（整批） | `全部左转/右转 90°` `横向左转/右转 90°` `方向复位` | 没有单页入口。复位＝清人工、回到自动默认 |

⭐ **页码互斥**：把某行改成已占用的页时**自动对调**（不是覆盖），
绝不会出现两行抢同一页 → 害得某份原件拿不到封面。

表格列：`# / 原件 / 页数 / 首页尺寸 / 扫描页 / 扫描页尺寸 / 方向 / 状态 / 说明`。
右键只有「改用扫描件第…页」「忽略此行」「显示原件」。

选项区三个勾选 + 后缀框：扫描页缩放到原件首页尺寸（默认开）／覆盖同名文件（默认关）／
连同子文件夹一起处理（默认关）。

配置记录：`~/.pdf_batch_cover_swap.json`（**和 v1 的 `.pdf_firstpage_swap.json` 各记各的**）。

## 验证口径

改完代码必须重跑（见 `mac/_regress/`）：

| 层 | 脚本 | 项数 |
|---|---|---|
| ① 核心自测 | `_regress/selftest.py`（纯标准库造 PDF，产物在 /tmp） | **106** |
| ② 界面端到端 | `_regress/verify_gui_e2e.py`（真建界面真点按钮） | **82** |
| ③ 记住上次选择 | `_regress/verify_config_memory.py` | **34** |
| ④ 真实语料 | `_regress/verify_real_corpus.py`（真实 WI，只读） | **38** |
| Windows 包 | `_regress/run_win.command`（同步 + 静态 + 真跑环境流程） | **44** |

一条命令跑全部：`./_regress/run_all.command`。

硬判据：输出第 1 页的文字 = 扫描件第 N 页；第 2 页起与原件**逐页**一致；页数不变；
**原件 md5 不变**；首页尺寸贴合（**按显示尺寸**算）。

> ⭐ `[1b]` 是**结构断言**：`winfo_reqwidth()/reqheight()` 必须 ≤ 默认窗口尺寸，
> 且三个模块确实各占一行 —— 能直接拦住「又不小心把按钮堆回一行」的回归。

## 依赖

- Python **3.9+**
- `pypdf >= 3.16`（读写 PDF 页面、`Transformation` / `transfer_rotation_to_content`）
- `tkinter`（标准库自带）

> v1 还要 `Pillow`（把图片扫描件转 PDF）；**v2 的扫描件就是一份 PDF，不需要 Pillow**。

国内直连 PyPI 慢，`setup_env.py` 会先走清华镜像、失败再退回官方源。

## 已知限制

- 扫描件**必须是一份 PDF**（不支持一堆图片）。
- **扫描仪多扫了空白页会让后面全部错位** —— 目前靠数量闸门 + 用户自己核对，
  没有做空白页检测（那需要渲染，会引入 pymupdf 依赖）。
- 原件只有 1 页时，输出就等于那一页扫描页。
- 模块①只能"整条链反过来"，不能处理"只有中间某几页乱序" —— 那种用模块②对调页码。
- **方向只能靠人眼判**：躺着的字和正着的字在程序看来都是一堆墨迹。工具只做
  「横向原件默认左转 90°」这一条默认规则，剩下交给整批按钮。
- 真正的「双击 `.bat` 能不能开」只能在 Windows 上点一次才算数（Mac 上跑不了 `cmd`）。
